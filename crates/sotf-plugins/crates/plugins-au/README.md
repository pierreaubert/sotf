# SOTF Audio Units

macOS Audio Unit (AUv3) plugins built from the SOTF Rust audio processing core. Each plugin in `sotf-plugins` is exposed as a `.appex` extension inside the `SOTFAudioUnits.app` container.

The build pipeline produces **two independent per-arch packages** (arm64 and x86_64) — no universal binary, no `lipo`.

## Layout

```
crates/sotf-plugins/crates/plugins-au/
├── project.yml                      # XcodeGen spec (one target per AU + container)
├── SOTFAudioUnits.xcodeproj/        # generated by xcodegen
├── Justfile                         # build / sign / notarize / dist recipes
├── Shared/
│   ├── BridgingHeader.h
│   └── sotf_audio_plugin_ffi.h      # copied from plugins-ffi
├── GenericAU/                       # shared Swift base class for every extension
├── EQAudioUnit/                     # one dir per AU extension target
├── CompressorAudioUnit/
├── …
├── App/                             # SwiftUI container app (registers all extensions)
├── Resources/
│   ├── libsotf_audio_plugins_ffi.a  # per-arch (overwritten between builds)
│   └── libsotf_gpui_au.a            # per-arch (overwritten between builds)
└── build/                           # isolated per-arch DerivedData
    ├── au-arm64/Build/Products/Release/SOTFAudioUnits.app
    └── au-x86_64/Build/Products/Release/SOTFAudioUnits.app
```

## Building

### Host arch (fast iteration)

```bash
just install-au-all
```

Builds the FFI staticlib for the host arch, runs `xcodegen` if needed, runs `xcodebuild` for the `SOTFAudioUnits` scheme, and copies `SOTFAudioUnits.app` to `~/Applications/`.

**Then launch the app once** so macOS registers each bundled `.appex` extension.

### Both arches (release flow)

```bash
just build-au-all                    # build both
DEVELOPER_ID="Developer ID Application: Your Name (TEAMID)" \
  just sign-au                       # sign both
APPLE_ID="you@example.com" \
  just sign-au-notarize              # notarize + staple both
just dist-au                         # zip both into dist/au/
```

Each step has per-arch variants (`build-au-all-arm64`, `sign-au-x86_64`, `dist-au-arm64`, etc.). Run `just --list | grep au` to see them all.

## Testing

After installing and launching `~/Applications/SOTFAudioUnits.app`:

- **In a DAW** (Logic Pro / GarageBand / Reaper / Ableton): insert an audio effect and look under "SOTF: …".
- **From the terminal**:
  ```bash
  just validate-au-all   # auval on every SOTF subtype
  just list-au           # pluginkit listing of registered AUs
  ```

For a single AU:

```bash
auval -v aufx SOEQ SOTF      # Audio Unit Effect, subtype SOEQ, manufacturer SOTF
```

## Adding a New Audio Unit

1. Add the plugin crate (`crates/sotf-plugins/crates/sotf-plugin-<name>/`) and re-export it from `sotf-plugins`.
2. Wire it into `crates/sotf-plugins/crates/plugins-ffi/src/plugin_factory.rs` (`match` on `plugin_type`).
3. Add a target in `project.yml` mirroring an existing AU. Pick a unique 4-character `Info.plist` subtype.
4. Create `<NewName>AudioUnit/` with `Info.plist` and a Swift file subclassing `GenericAU`.
5. Rebuild: `just build-au-all` (or one arch) and re-install.

XcodeGen rewrites `SOTFAudioUnits.xcodeproj` automatically when `project.yml` changes.

## Troubleshooting

### Plugins not showing in the DAW

```bash
ls -d ~/Applications/SOTFAudioUnits.app
just list-au
killall -9 AudioComponentRegistrar coreaudiod
open ~/Applications/SOTFAudioUnits.app   # launch once to register
```

### Build errors

```bash
# Confirm the staged staticlib is the right arch
file crates/sotf-plugins/crates/plugins-au/Resources/libsotf_audio_plugins_ffi.a
# arm64 or x86_64 — should match the target you're building
```

If you see `lipo: can't open input file`, you're on a stale recipe. The current pipeline doesn't use `lipo` at all — pull the latest `Justfile`.

### Runtime crashes

- Crash logs: `~/Library/Logs/DiagnosticReports/`
- DAW logs: `log stream --predicate 'process == "Logic Pro"' --level debug`
- Look for FFI boundary issues (null pointers, memory) — enable Address Sanitizer in the Xcode scheme.

## Distribution

Output zips live in `dist/au/`:

- `SOTFAudioUnits-<VERSION>-macos-arm64.zip`
- `SOTFAudioUnits-<VERSION>-macos-x86_64.zip`

Each is built with `ditto -c -k --keepParent` so resource forks and the notarization ticket survive transit. End users download the zip matching their Mac's CPU, drag `SOTFAudioUnits.app` into `/Applications` (or `~/Applications`), and launch it once to register the extensions.
