# plugins-au

Swift Audio Unit (AUv3) plugin wrapper for macOS. Builds **per architecture** (arm64 + x86_64) — no universal binary, no `lipo`. Each arch produces an independently signable, notarizable, distributable bundle.

## Platform

macOS only.

## Build

This is a Swift/Xcode project, not a Rust crate. Driven by `Justfile` recipes.

```bash
# Build (host arch) + install to ~/Applications/SOTFAudioUnits.app
just install-au-all

# Build a specific arch only
just build-au-all-arm64
just build-au-all-x86_64

# Build both arches (release flow)
just build-au-all

# Validate registered AUs
just validate-au-all
```

After install, **launch `~/Applications/SOTFAudioUnits.app` once** so macOS registers each `.appex` extension. The AUs then appear in any AUv3 host (Logic, GarageBand, Ableton, etc.).

Per-arch outputs land at:

```
crates/sotf-plugins/crates/plugins-au/build/au-arm64/Build/Products/Release/SOTFAudioUnits.app
crates/sotf-plugins/crates/plugins-au/build/au-x86_64/Build/Products/Release/SOTFAudioUnits.app
```

## Sign / notarize / distribute

Operates on the per-arch BUILD output, not on `~/Applications/...`:

```bash
DEVELOPER_ID="Developer ID Application: Your Name (TEAMID)" \
  just sign-au               # both arches
APPLE_ID="you@example.com" \
  just sign-au-notarize      # both arches
just dist-au                 # → dist/au/SOTFAudioUnits-<v>-macos-{arm64,x86_64}.zip
```

Per-arch variants exist for each step (`sign-au-arm64`, `dist-au-x86_64`, etc.) — see `Justfile`.

## Dependencies

- `plugins-ffi` — Rust FFI bindings (compiled to a per-arch staticlib)
- `gpui-au` — GPUI rendering helpers (also per-arch)
- `xcodegen` (`brew install xcodegen`) — regenerates `SOTFAudioUnits.xcodeproj` from `project.yml`

## Notes

- The Swift code interfaces with Rust through `Shared/sotf_audio_plugin_ffi.h` (generated by cbindgen in `plugins-ffi`).
- The Xcode project links `-lsotf_audio_plugins_ffi`; cargo emits `libplugins_ffi.a`, so the build recipes copy it into `Resources/libsotf_audio_plugins_ffi.a` under that name.
- `Resources/lib*.a` files are per-arch and **overwritten between arch builds**. Each `xcodebuild` step finishes before the next arch's `cargo build` replaces them, so the link inputs always match the arch under build.
- `xcodebuild` is invoked with `-derivedDataPath build/au-<arch>` so the two arches don't clobber each other's intermediates.
- All AU extensions share `CFBundleShortVersionString` (Apple requirement). The `sync-au-versions` recipe propagates the workspace `Cargo.toml` version into every `<Name>AudioUnit/Info.plist` and `project.yml:MARKETING_VERSION`; it runs automatically before each build.
- For doc and architecture details, see `SETUP_GUIDE.md` (full) and `QUICKSTART.md` (5-minute path).
