# EQ plugin code review — 2026-08-12

## Remediation status

Implemented in `0.5.69`:

- **Fixed:** SVF banks now use each channel's own filters, and coefficient transitions retain
  per-channel old/new stage coefficients.
- **Fixed:** unsupported SVF plus internal oversampling is rejected, keeping reported latency
  consistent with the selected audio route.
- **Fixed:** standard biquad construction rejects invalid channels/sample rates, non-finite or
  out-of-range frequency/Q/gain, and frequencies at or above Nyquist.
- **Fixed:** ordinary processing checks multiplication and buffer bounds, copies only the active
  region, and leaves oversized output tails untouched.
- **Fixed:** Auto Gain and Oversampling are included in schema and current-value snapshots.
- **Fixed (0.5.72):** type-specific high-order Q semantics, transactional filter replacement,
  bounded oversampling preallocation, and UI/preview parameter parity are covered by focused tests.
- **Fixed (0.5.73):** coefficient-transition progress is measured in source-frame time even though
  the interpolation loop runs at the oversampled rate. Real-audio Q, gain, and type edits last the
  documented five milliseconds at Off/2x/4x and across single-sample, irregular, and whole-window
  callback partitions. `per_channel_audio_transitions_match_independent_mono_references` further
  verifies processed stereo frequency, Q, gain, and type edits sample-for-sample against two
  independently stateful mono plugins for every oversampling factor and callback partition shape.

- **Fixed (0.5.70 follow-up):** warped-biquad filters retain whether `lambda` was omitted and
  recompute the automatic Bark-scale value during sample-rate reinitialization. Explicit lambda
  values remain unchanged. Added `test_automatic_warped_lambda_tracks_sample_rate`.
- **Fixed (0.5.71 follow-up):** engine EQ settings now carry and round-trip the full global
  parameter set, including `auto_gain_enabled` and `oversampling`; the accessor test locks the
  field/spec count and runtime update behavior.
- **Fixed (0.5.72 completion):** high-order peak/notch/bandpass/all-pass cascades preserve
  user Q and have magnitude/phase regression tests; structural replacement is validated,
  transactional, and rebuilds runtime/schema state; oversampling rejects blocks beyond its
  preallocated 4096-frame contract and has an active 4x allocation test; the custom/AU UI uses
  the five-field band model and order/sample-rate-aware preview; engine and both factories carry
  every global control; direct in-place buffer contracts and crate-version metadata are tested.

All P0-P3 findings below are now closed. The steady-state path retains its allocation-free
specialized stereo loop; broader SIMD/layout changes remain optional benchmark-driven evolution,
not an open correctness defect.

## Findings

### P1 — Per-channel EQ is lost in SVF mode and corrupted during every smoothed edit

`rebuild_svf_filters` iterates over the channel count but always builds every channel from `self.filters[0]` (`crates/sotf-plugins/crates/sotf-plugin-eq/src/lib/eq_plugin.rs:145-184`). Thus switching a genuinely per-channel configuration to SVF makes all channels use channel 0's curve. Biquad smoothing has the same ownership error: `set_parameter` captures only channel 0's old and new coefficients (`eq_plugin.rs:991-1008`, `1056-1072`), while both interleaved and oversampled processing apply that single transition to every channel (`eq_plugin.rs:519-557`, `1248-1284`). A right-channel band with different frequency/Q/gain is temporarily processed with channel 0's coefficient trajectory, then snaps back to its own final coefficients when the shared transition ends.

This is a confirmed audible correctness defect, not merely an optimization concern. Store transition coefficient pairs per channel and build SVFs from `self.filters[ch]`. Add two-channel impulse/sine tests with deliberately different curves; exercise frequency, Q, gain and type edits in both normal and oversampled paths, plus Biquad→SVF switching, and compare each channel against an independent mono reference throughout the transition.

### P1 — SVF plus oversampling reports latency that the audio path never incurs

Setting `oversampling` constructs an `Oversampler` and makes `latency_samples()` report its delay (`eq_plugin.rs:816-840`, `1198-1203`). But `process_in_place` checks SVF first and processes it directly; the oversampling branch is never entered when SVF banks exist (`eq_plugin.rs:1226-1242`, `1300-1322`). The host therefore applies delay compensation for nonexistent latency, misaligning this plugin with parallel paths. Oversampling also has no sonic effect in SVF mode despite round-tripping as enabled.

Reject this unsupported combination, or route SVF through the oversampler and design it at the oversampled rate. Compile metadata and reported latency must describe the route actually executed. Add a combined topology/oversampling matrix test that measures impulse delay and frequency response, not only finiteness and parameter round-trip.

### P1 — High-order Q semantics are wrong for notch, bandpass and all-pass filters

For order greater than two, `create_band_stages` uses the requested Q only for Peak/PeakMatched; every other type receives only the Butterworth prototype Q (`crates/sotf-plugins/crates/sotf-plugin-eq/src/lib/misc.rs:22-53`). The comment mentions LP/HP/shelf, but the wildcard also includes Notch, Bandpass and AllPass. Consequently changing Q on a fourth-/sixth-/eighth-order notch or bandpass does not implement the advertised bandwidth control, and `get_parameter` reports the primary stage's prototype Q instead of the requested Q (`eq_plugin.rs:1087-1123`). The UI/docs still expose Q uniformly.

Define type-specific high-order designs. LP/HP can use Butterworth section Qs; peak/notch/bandpass/all-pass need an explicit meaning for user Q and a response-derived design rather than falling through a wildcard. Preserve the user value separately from derived section Qs. Add magnitude/phase tests for every filter type and order, asserting center/cutoff behavior, slopes, and that Q changes bandwidth where advertised.

### P1 — Standard biquad preset construction bypasses the plugin's validation contract

Factory JSON is deserialized and passed directly to `EqPlugin::from_params` (`crates/sotf-plugins/src/factory/create.rs:88-92`). The standard-biquad branch validates only filter type and even order, then clamps Q and calls the permissive `Biquad::new` (`crates/sotf-plugins/crates/sotf-plugin-eq/src/lib/eq_plugin.rs:306-345`). It never rejects non-finite Q, frequency/gain outside the advertised ranges, or gain large enough to overflow coefficient calculations. Advanced filters do call `validate_freq_q_gain` (`src/lib/advanced_filter.rs:20-38`), so the same config fields have topology-dependent validation. `NaN.clamp(...)` remains NaN and can yield non-finite standard-filter coefficients/output through the programmatic constructor; extreme finite JSON gain is also accepted.

Use one fallible validation routine for all topologies before construction, including finite sample rate/frequency/Q/gain, frequency below Nyquist, the documented Q ceilings and `[-24, 24] dB`. Prefer `Biquad::try_new` after plugin-level range checks. Add factory and direct-constructor tests for boundaries, low sample rates, NaN/infinities (direct serde values), and extreme finite JSON.

### P2 — Default warped-biquad tuning becomes stale after a sample-rate change

When `lambda` is omitted, construction computes `bark_lambda(sample_rate)` (`src/lib/advanced_filter.rs:22-38`), matching the documentation's “active sample rate” promise. The runtime does not remember that lambda was automatic. Reinitialization calls `update_params` with the old numeric lambda (`advanced_filter.rs:62-75`), so a 44.1→96 kHz change retains the 44.1 kHz warp. The existing sample-rate test uses an explicit lambda and only checks that the call succeeds (`src/lib/tests.rs:1524-1541`), missing the default case.

Retain `Option<lambda>`/an automatic flag in the runtime and recompute Bark lambda whenever sample rate changes only for automatic mode. Compare warped frequency responses after direct construction at the destination rate versus reinitialization from another rate; separately prove explicit lambda remains fixed.

### P2 — Public filter replacement leaves schema and alternate topology state stale

`set_filters` and `set_channel_filters` replace the biquad banks but do not rebuild `cached_parameters`, rebuild active SVFs, apply the current sample rate/oversampling factor or propagate `use_tdf2` (`eq_plugin.rs:438-461`). After construction, the host can therefore keep parameter IDs for removed bands, omit new bands, continue hearing the old SVF bank, or receive filters designed for a caller-supplied rate rather than the initialized plugin rate. Their tests inspect only the private vectors (`src/lib/tests.rs:1459-1510`).

Make replacement a fallible, control-thread structural operation that validates channel/band shapes, normalizes all stages to current runtime settings, rebuilds topology state and cached metadata atomically, and specifies whether histories reset or crossfade. Test replacement after initialization under TDF-II, SVF and oversampling, then verify schema/current values and output against a newly constructed reference.

### P2 — The ordinary process path can panic and has inconsistent active-region semantics

The adapter path performs `output.copy_from_slice(input)` before calculating `num_frames * channels` (`eq_plugin.rs:756-764`), so unequal whole-slice lengths panic even when both active regions are large enough. `process_in_place` then indexes the active region without any bounds/overflow check (`eq_plugin.rs:1205-1239`). By contrast, the compiled path checks multiplication and both slice sizes and copies only the active samples (`eq_plugin.rs:624-675`). Auto-gain measurement is also given the entire regular buffer rather than the active region (`eq_plugin.rs:1222-1224`, `1326-1328`), so oversized/stale tails bias the loudness estimate.

Share the compiled path's checked sample-count helper, return `Err` for undersized buffers, copy/process/measure only `[..sample_len]`, and document oversized-tail behavior. Test zero frames with nonempty buffers, unequal oversized slices, undersized input/output, multiplication overflow, and parity between compiled and ordinary entry points.

### P2 — Advertised auto-gain and oversampling controls are deliberately absent from host schema/state

The setter/getter implements `auto_gain_enabled` and `oversampling`, but `rebuild_cached_parameters` registers neither (`eq_plugin.rs:187-260`, `810-840`, `1087-1098`). `current_values` iterates only that cache (`eq_plugin.rs:723-730`), so generic UI, automation/preset snapshots and schema-based validation cannot discover or preserve these audible/latency-changing settings. Tests explicitly lock in their absence (`src/lib/tests.rs:1727-1770`), while `USAGE.md` documents Auto Gain as a normal parameter and the catalog claims plugin-reported oversampled latency (`crates/sotf-plugins/src/factory/catalog.rs:438-457`). Advanced warped/Kautz configuration is likewise config-only and absent from runtime state/schema.

Either register all supported controls and define preset migration, or remove the unreachable setter surface and clearly label these as construction-only. Latency-changing oversampling should be structural and force host graph/PDC recompilation. Add schema↔setter↔getter↔current-values completeness tests rather than tests that bless omissions.

### P2 — Oversampling can allocate on the realtime thread for blocks beyond its warm-up assumption

The EQ oversampling route calls the shared `Oversampler::process` from the audio callback (`eq_plugin.rs:1300-1322`). Its buffers are preallocated around a hard-coded 4096-frame expectation, but `ensure_residual_in_capacity` and residual-output handling call `Vec::resize` when exceeded (`crates/sotf-plugins/crates/sotf-host/src/oversampling/oversampler.rs:156-178`, `225-236`, `267-278`). The EQ's allocation test uses an empty, non-oversampled 512-frame chain (`crates/sotf-plugins/crates/sotf-plugin-eq/src/lib/tests.rs:283-304`); the workspace allocation test is also non-oversampled (`crates/sotf-plugins/tests/realtime_allocation_tests/tests.rs:80-101`).

Make the maximum block size an initialization/build contract and preallocate for it, or reject oversized blocks without allocating. Add zero-allocation tests for active 2x/4x filters, transitions, auto-gain measurement boundaries and the largest supported block/channel count. Formatting/logging on oversampler error paths should also remain off the callback.

### P3 — The steady-state hot loop leaves available block processing performance unused

The normal interleaved loop converts every sample to f64 and calls `Biquad::process` for every stage (`eq_plugin.rs:581-621`, `1248-1298`). That rechecks the DF-I/TDF-II choice per sample and cannot use the dependency's contiguous `process_block` kernels; channel-major state stored behind nested `Vec`s is traversed from a frame-major buffer. The transition path additionally interpolates five coefficients for every stage, channel and sample. This is allocation-free in supported small blocks, but cost scales poorly toward 20 bands and high channel counts.

Benchmark 2/6/8/12-channel, 1/10/20-band and order 2/8 cases before refactoring. Candidates are reusable planar/channel scratch, specialized stereo loops, hoisting realization dispatch per block, and a state-safe output crossfade or physical-parameter ramp that avoids repeated coefficient reconstruction. This is an algorithm/performance recommendation, not a demonstrated functional regression.

### P3 — UI/docs and implementation describe different parameter models

`UI.md` and `USAGE.md` use `band_{n}_type`/`filter_{band}_...` in places, while the implementation exposes `band_{n}_filter_type` and five fields per band including order (`eq_plugin.rs:204-260`). The custom UI indexes only four fields (`src/ui/render.rs:283-288`, `390-406`, `472-479`) and renders second-order preview biquads at a fixed preview rate (`src/ui/calculate.rs:12-44`), so it cannot visualize high-order, SVF, warped or Kautz response accurately. Rendering also allocates signature/label/control vectors and takes a global cache mutex on the UI thread (`src/ui/render.rs:40-104`); this is not audio-thread unsafe but is worth profiling during drag automation.

Define one parameter-index/key model and make preview data come from the actual DSP topology/order/sample rate. Add screenshot/response parity tests for each supported topology and high-order curve, plus a mapping test from every UI gesture to the intended engine key.

## Algorithm and realtime assessment

The order-2 RBJ/Orfanidis biquad path is conventional, denormal handling is explicit, reset clears Biquad/SVF/advanced/auto-gain/oversampler histories, and the no-oversampling steady-state path returns `context.num_frames` without allocation, locking or logging. Coefficient interpolation is stable for normalized stable second-order denominators because the dependency documents a convex Schur/Jury region; the main problem is ownership across channels, not linear interpolation itself. Direct coefficient morphing can still create non-monotonic audible magnitude trajectories, so response-bounded automation tests should cover sine and programme material rather than only finite/DC output.

Oversampling correctly designs standard biquads at the oversampled rate and restores the temporarily moved oversampler across unwind. Its chunk/residual design adds reported latency and intentionally fills startup with zeros. That contract is sound only when the route is actually used (not SVF), the host recompiles PDC after structural changes, and the block-size preallocation bound is enforced.

There is no plugin-local bypass control; bypass is assumed to be host-owned and should preserve/reset histories according to the host contract. Channel count is fixed after construction, input/output counts match, and advanced filters are zero-latency after any oversampling delay. Auto gain is post-EQ, bounded/smoothed by the shared host component, but its measurement must be restricted to active samples and its undiscoverable schema state fixed.
